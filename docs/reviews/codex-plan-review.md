1. **High — “Agents run without tools” is false for Codex.** Evidence: `omarchy-ai-playground/agent_run.py:67–76` explicitly excludes Codex from `NO_TOOLS`: its read-only sandbox still permits local file reads. The plan’s blanket guarantee (`maprisma-playground/docs/plan.md:18`) could lead an implementer to send it hostile captions or images. **Fix:** define separate capabilities for asking, accepting images, and reading untrusted input. Preserve the explicit untrusted-input allowlist; never infer safety from image support or a read-only sandbox.

2. **High — The subprocess safety contract omits process-tree termination and shutdown cleanup.** Evidence: the source starts a new process session, enforces output limits while reading, and kills the process group on overflow or timeout (`omarchy-ai-playground/ai_core.py:139–193`); startup also removes inherited agent-session variables (`ai_playground.py:491–492`). “Time limit and size limit” alone does not specify these behaviors. **Fix:** implement one shared runner with bounded streaming, concurrent stdin delivery, a deadline, process-group cancellation, environment cleanup, and a registry for shutdown. Test children that keep stdout open, ignore termination, or never read stdin.

3. **High — Media safety is substantially underspecified.** Evidence: pictures are checked *before decoding* against file size, dimensions, and total animated pixels (`omarchy-ai-playground/picture_check.py:11–13,94–105`). Video tools restrict protocols and container formats and optionally run under a memory limit (`chess_video.py:65–78`). YouTube downloads disable user configuration and execution hooks and validate the resulting path (`chess_video.py:89–105`). **Fix:** explicitly port these guards before implementing media UI. Scaling with `package:image` happens too late to prevent a decode allocation attack; ordinary ffmpeg invocation also loses the source’s playlist protections.

4. **High — Local HTTP security needs an explicit contract.** Evidence: `omarchy-ai-playground/loopback.py:36–41` rejects listeners belonging to another account; `netfetch.py:49–66` prevents local redirects and proxy use. The plan only says “loopback servers” (`docs/plan.md:43`). **Fix:** check listener ownership before requests, use literal loopback addresses, bypass proxies, reject redirects, and bound response sizes and deadlines. Apply this consistently to discovery, model queries, generation requests, and GPU/unload operations.

5. **High — “No shared Omarchy names” hides external configuration changes.** Evidence: Analyze can modify `~/.config/llama.cpp/models.ini`, configure Pi’s model entry, download a projector beside an existing model, and start a server (`omarchy-ai-playground/frame_check.py:438–465`). `local_hold.py:33–40,146–157` uses shared service/configuration names and stops only a server it started, provided no other client is connected. **Fix:** distinguish Playground-owned data from shared agent/model configuration. Specify backups, safe writes, service ownership, hold/release behavior, and Manager retention rules. Do not mechanically rename shared provider paths to Playground paths.

6. **Medium — Download parity means more than SHA-256 and exclusive creation.** Evidence: generation downloads safely reopen resumable `.part` files using `O_NOFOLLOW` and ownership/link-count checks (`omarchy-ai-playground/picture_gen.py:118–129`); projector staging additionally uses locking (`frame_check.py:270–291`). Release extraction rejects links, unexpected names, and excessive unpacked size (`picture_gen.py:223–241`). **Fix:** document separate resumable-download and archive-extraction contracts, including cancellation, size bounds, concurrent download handling, final promotion, and cleanup. “Opened exclusively” alone both omits protections and loses resumability.

7. **High — The stated sister-app single-instance pattern is wrong.** Evidence: Theme uses GApplication registration and remote actions (`maprisma-theme/flutter_app/linux/runner/my_application.cc:246–274`), hides on focused toggle, and hides on close (`:174–195`). It does not use the claimed runtime Unix socket. **Fix:** reuse GApplication/D-Bus and deliberately choose Playground’s lifetime policy. If closing really quits, retain that as an explicit divergence and define cancellation, temporary-file cleanup, and state saving. Forward validated `--agent`/`--test` arguments to the existing instance; Theme’s current parameterless show action is insufficient.

8. **High — Child processes do not guarantee a responsive Flutter UI.** Evidence: the plan makes that claim at `docs/plan.md:57–58`, whereas Theme runs its core in a background isolate (`maprisma-theme/flutter_app/lib/backend.dart:25–46`). Image decoding, hashing large models, chess calculations, and synchronous filesystem operations can still block Flutter. **Fix:** establish the isolate/backend interface in step 1, including progress, cancellation, request IDs, and stale-result rejection. Keep expensive Dart work outside the UI isolate.

9. **High — Chess parity omits an entire position editor and several controls.** Evidence: the source supports setup mode, choosing whose turn it is, clearing/resetting the board, and playing a constructed position as either side (`omarchy-ai-playground/chess_page.py:148–165`). It also has separate strengths for both agents and pause/resume (`:107–142`), plus automatic invalid-move retry (`:555–567`). These are absent from step 3’s acceptance list. **Fix:** add position editing—including piece-card placement/removal—side selection and orientation, independent strengths, pause/resume, undo behavior, agent commentary/errors, and manual/automatic retry to explicit acceptance criteria.

10. **Medium — Saved games and video import are reduced too far.** Evidence: the plugin has a separate Games page (`omarchy-ai-playground/ai_playground.py:181`), searchable/paginated game listings (`chess_import.py:780–795`), original-source opening (`:829–842`), automatic replay (`:986–1004`), and same-source replacement (`:512–515`). Import also exposes reader selection, frame interval, duration limit, cost warnings, and fast-text fallback to frames (`:353–389`), with cancellation (`:157`). **Fix:** enumerate these behaviors, duplicate/replacement semantics, saving played games, and partial/failed import outcomes. Include the Games page in the architecture and screenshot checklist.

11. **Medium — Analyze’s “frame_check” shorthand conceals a user-visible setup workflow.** Evidence: Analyze exposes a projector download button, progress, retry, cache invalidation, and re-analysis (`omarchy-ai-playground/analyze_tab.py:100–165`). Its seven cards include context, thinking, and picture generation as well as live probes (`analyze.py:39–56`). **Fix:** list all seven cards and distinguish measured results, advertised capabilities, unknown/skipped states, local configuration repair, and optional downloads. Move the shared vision readiness/setup service ahead of video import, which already depends on it.

12. **Medium — Smaller parity gaps and invented settings need resolving.** Evidence: Generate has size selection, cancellation, multiple result pictures, clear, and displayed seeds/timing (`omarchy-ai-playground/generate_tab.py:48–74,180–199`). Speed and Duel accept local models alongside agents (`tabs.py:127–148`); sequential runs unload models (`:150–154`). Settings’ “Several local models at once” is an explanation of a per-run dialog, not an ask/allow preference (`ai_playground.py:454–469`); Corners is a real preference (`:421–425`). Esc/Backspace navigation is also implemented (`:303–306`). **Fix:** add these behaviors to a parity checklist, remove the invented persistent GPU policy, and explicitly decide whether Corners is retained or excluded.

13. **High — Bundling only `[ask]` data cannot reproduce agent readiness.** Evidence: readiness uses adapter access metadata, credential-file existence/environment variables, and configured local providers (`omarchy-ai-playground/chess_page.py:371–385`; `agent_status.py:418–450`). The source deliberately avoids reading credential contents (`agent_status.py:7–9`). **Fix:** bundle the four agents’ access and provider-detection metadata alongside their ask tables. Specify stat-only credential checks and local-provider readiness. Clarify whether “signin” means detection or an actual sign-in feature; the latter requires its own terminal/key-handling design.

14. **High — Bar integration is plausible, but the Theme analogy is incomplete.** Evidence: Theme’s COSMIC desktop entry includes `X-CosmicApplet` and `X-HostWaylandDisplay` (`maprisma-theme/cosmic/applet/data/io.github.ubruckhaus.CosmicMaprismaTheme.desktop:7–13`). KDE’s tray is implemented by the **Dart core daemon**, not a Rust tray (`packages/maprisma_theme_core/lib/src/daemon.dart:1–6,150–163`), and it re-registers when the watcher returns (`:454–478`). **Fix:** identify the Rust tray as a new implementation choice. Require singleton ownership, watcher restart recovery, KDE-only autostart, immediate startup after installation on KDE, correct icon names, and absolute executable resolution. Test the proposed title/id against the actual Maprisma Icons widget; a title prefix alone is not an integration test. Leave COSMIC panel placement to Manager/user configuration.

15. **High — “Atomic swap” is not a sufficient installer specification.** Evidence: Theme stages and validates the complete bundle, stops processes by executable path, swaps directories, installs the compiled core and applet, writes escaped absolute desktop commands, adds a hidden Toggle entry, refreshes caches, and restarts the KDE daemon (`maprisma-theme/tools/install-local:24–35,37–95`). **Fix:** enumerate this installer contract, including `--no-build` semantics, XDG paths, CLI/bar links, installed assets, and process shutdown. For Playground, explicitly handle active downloads/generation and agent children before replacing a running bundle.

16. **High — Manager needs a complete lifecycle entry, not just files and `BarIcon`.** Evidence: Theme’s entry contains `open`, `appIcon`, repository inputs, `flutter: FlutterEnv.dir`, `stopsOwnProcesses`, prerequisites, tree ownership, key executable, link targets, data retention, process matching, full bar fields, version detection, and post-steps (`maprisma-manager/packages/maprisma_manager_core/lib/src/catalog.dart:271–334`). **Fix:** derive Playground’s entry from its finished installer. Include its public GitHub mapping, core/applet/tray paths, both desktop launch entries, config/model data, `ProcessMatch.exeUnder`, `cosmicAppletExe`, KDE autostart/executable/arguments, actual SNI icon name, and installed version metadata. Keep model downloads as retained user data. Add catalog/install/remove/bar checks and reconcile `docs/inventory.md` with the resulting files.

17. **High — The work order postpones the riskiest integration, and the two-person split is incomplete.** Evidence: video import precedes its shared `frame_check` dependency, install/bar integration waits until step 7, and implementer ownership is specified only for steps 1 and 3 (`docs/plan.md:86–105`). **Fix:** first agree on typed agent/results, settings schema, cancellation/progress, board/controller interfaces, and a feature matrix. Assign implementer A the core runner, agents/providers, media/download safety, and CLI; implementer B the native Flutter shell, widgets/pages, bar, installer, and Manager integration. A owns chess state/rules/controller; B owns board rendering/input through an agreed interface. Begin with an installed vertical slice on KDE and COSMIC, then add shared vision readiness before video import. Review each other’s changes and integrate after every slice.

18. **Medium — Validation and publication gates need strengthening.** Evidence: planned widget tests cover only header/tabs/cards/board, and fake-agent testing names only Claude (`docs/plan.md:110–118`). That misses four distinct argv/stdin behaviors, native remote activation, compositor screenshots, installer paths, tray recovery, and Manager removal. Also, chess currently sends prompts through argv (`omarchy-ai-playground/chess_agent.py:146–157`), despite the plan claiming stdin parity. **Fix:** test all four adapters and route chess through the shared stdin-aware runner as a deliberate improvement. Add process/media/network fault tests and native install/toggle/bar smoke tests on both desktops. Establish reference captures before implementation and compare interaction/error states as well as tabs. Before publishing under MIT, preserve upstream notices and audit copied assets: `omarchy-ai-playground/icons/Asterism/COPYING:4–6` identifies additional icon/font licenses.
